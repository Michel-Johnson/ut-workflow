# UT 工作流

交付符合 UT 规范的测试代码、真实执行证据和验收结论。质量标准与执行流程分开；本文只说明如何选择材料、执行测试任务及处理失败。

## 先选择任务入口

| 请求 | 动作范围 | 按需读取 |
| --- | --- | --- |
| 新建或补充单测 | 测试代码及必要测试配置 | [生成与验证](references/test.md) |
| 修复失败或陈旧单测 | 先归因，仅修测试问题 | [失败决策](references/failure-decisions.md)、test.md |
| 执行单测、统计覆盖率 | 默认不改代码；按项目命令执行 | test.md 的验证/覆盖率部分 |
| 按规范审查单测 | 默认只读，输出证据与问题 | [审查流程](references/review.md) |

被测生产逻辑只读。发现业务缺陷，保留正确断言、复现和修复建议；业务修复是另一项任务，不通过本 Skill 擅自执行。只要求运行或审查时，不自动补写测试。

## 读取规范与项目事实

- [UT 规范](references/testing-standard.md)：范围与预期 UT-01～04；设计 UT-05～08；隔离 UT-09～13；执行 UT-14～17；覆盖率 UT-18～20；验收 UT-21～23。只加载当前任务相关部分。
- [方法选择](references/test-techniques.md)：场景或 Oracle 设计需要补充手段时读取。
- [结果记录](references/result-recording.md)：整理缺陷状态与报告时读取。
- [项目配置](references/project-profile.md)：测试入口、模块、运行时、预算或覆盖率要求不明确时读取；优先使用项目已有配置。
- 框架用法先核对项目依赖版本和邻近测试，知识不够时再查对应版本官方资料；不预读所有语言文档，不默认安装最新框架。

规范可供人工独立使用。Skill 不批准规范例外；项目已有更具体要求时核验适用性，冲突必须说明，不能把偏离称为符合。

## 执行闭环

1. **确认范围与预期**：读取请求、适用项目约定和工作区已有修改。显式范围不因 Diff 自动缩小；Diff 任务明确比较基线和实际被测快照。关键预期无法确认时澄清，契约明确的独立场景可以继续。
2. **确认测试入口**：识别目标模块、现有测试风格、命令和副作用。不要把真实外部调用或付费评测当离线 UT。需要区分历史失败时先建立相关最小基线；无法运行则记录 baseline_unknown。
3. **设计并生成**：生成/补测任务列行为、场景、Oracle 和观察方式后写测试；沿用项目组织方式，按风险覆盖边界与异常。纯运行/审查任务跳过写入。
4. **真实验证并归因**：记录命令、工作目录、退出码、发现数和结果。任何阶段的新失败都进入失败决策；允许新增缺陷候选。探测通过但未证明路径和断言有效时，只标未复现。
5. **按规范验收**：检查适用规则、实际范围和证据完整性。失败/未执行目标不从门禁分母消失。分别报告测试质量、实际执行结果与任务完成度，不声称整个项目可发布或可合并。

只有测试或必要测试配置的修改才能在本任务内修复。不得弱化断言、吞异常、删除有效失败证据或改生产逻辑让测试通过。修正无效测试构造时记录原因。

## 何时结束

约定范围的补测和验证已完成时结束；若正确测试已证实业务缺陷，保留复现即可交付补测结果，同时说明执行失败、业务修复待办。缺少必要权限/输入、耗尽项目预算，或重复同一失败没有新信息时，保存证据并说明未完成项。

不固定每函数入口数和重试次数；遵守项目预算，在新修改、新失败或未解决风险出现时才扩大验证。覆盖率补测照常分析失败，不因阶段不同删除证据。

## Agent 与程序分工

Agent 负责理解行为、选择场景、判断因果与审查证据；测试框架负责实际执行。需要机器可读汇总时，可用 [gate_report.py](scripts/gate_report.py)：

```bash
python3 <skill-dir>/scripts/gate_report.py <checks.json>
```

输入和退出码见 `--help`。脚本只检查规则记录完整性并汇总，不运行测试、不验证证据真实性、不批准例外；输出 READY 仅汇总给定质量规则，不代表测试执行通过。

## 交付

按 [结果记录](references/result-recording.md) 给出必要字段，分别说明测试质量、实际执行结果和任务完成度。正确单测发现业务缺陷不等于测试质量不合格。未运行、零发现、跳过、静态发现与运行确认不能混淆。
