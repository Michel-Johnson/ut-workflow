# 测试入口

## 选择目标与 Oracle

保留显式函数/文件/包范围；Diff 仅在用户要求或未指定范围且存在可用变更时作为范围。大任务按模块或风险分批，记录未完成目标，不能按字母取前 N 个后宣称全部完成。

读取完整目标实现、必要直接调用与类型、邻近测试和需求契约。证据仍不够时沿相关调用链定向追踪，不以“一层”作为真相边界，也不无边界扫描全仓。

每个行为写下：初始状态、输入/动作、依赖结果、正确期望、观察方式、依据。需求不明时不要照搬当前输出；关键歧义需澄清，独立且契约清楚的场景可先推进。

## 组织与生成

先检查项目能否发现测试、依赖是否就绪。命令缺失时根据实际框架构造最小入口，不能用临时独立工程通过来冒充目标项目成功。没有项目测试框架时优先语言内建/同类模块已有方案，不机械引入某个第三方工具。

按行为组织命名测试、Subtest 或参数化项；场景数取决于逻辑，不固定每函数至少几个 Case。关键 Arrange 信息靠近用例，Fixture 不隐藏触发条件。

Mock 只处理必要边界。关注输入/类型/错误契约以及是否实际命中被测路径；不要验证与需求无关的内部调用顺序。中文或 Unicode 测试输入不受标识符风格限制。

## 验证

先运行本次最小相关范围，记录发现数、退出码与真实结果。生成前基线或同快照对照帮助判断历史问题；无法取得时标记 baseline_unknown。

按 [失败决策](failure-decisions.md) 处理任何失败，包括补覆盖率期间。修改测试/配置后重跑；影响共享资源时扩大相关回归。test-only 遇到生产缺陷，保留复现和建议，不擅自修生产。

## 覆盖率仅在需要时

读取项目阈值/口径；用户未要求且项目没有规定时无需强制引入覆盖率工具。明确要求但工具不可用时输出未验证，不视为无要求。

合法空目标、配置缺失与工具错误分别处理。可分模块/分片执行，合并前核验同一被测快照、目标完整性与插桩兼容。失败/未执行目标不从必需验收范围消失。

补测针对有价值的未验证行为，不能仅追逐执行行。新增补测失败照常分析，允许发现新缺陷；只有已证明无效的测试构造才能撤回。覆盖率达标不覆盖执行失败或无效断言。

## 结束

按 [结果记录](result-recording.md) 分别报告测试质量、实际执行结果和任务完成度。正确测试稳定暴露业务缺陷时，补测可完成，但执行失败。静态问题不是运行证据。

场景设计需要性质、状态模型或 Fuzz 等方法时，按需读取 [方法选择](test-techniques.md)。
