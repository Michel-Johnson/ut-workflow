# UT 生成、执行与验收规范

版本：1.0.2。适用于人工和 Agent 生成、维护、执行及审查单元测试；不规定业务开发、集成/E2E 或发布流程。

本规范定义质量要求，不限定测试框架、入口数量、修复轮次或统一覆盖率阈值。规则编号保持稳定；只检查适用规则，不要求每次填写全表。

## 1. 范围与正确预期

| 编号 | 适用条件 | 要求 |
| --- | --- | --- |
| UT-01 | 所有 UT 任务 | 明确范围、被测代码状态和目标行为；不擅自扩大、缩小或截断范围。 |
| UT-02 | 新增或修改断言 | 预期有需求、接口契约或不变量依据；不以当前错误输出作为答案。 |
| UT-03 | 新增或改变行为 | 覆盖适用的主路径、重要分支、边界、错误和状态变化；关键遗漏说明原因。 |
| UT-04 | 回归测试 | 能触发原问题并验证正确行为；保留失败与修复后证据，无法验证的部分明确说明。 |

关键预期不明时不得臆造。遗留行为可用刻画测试记录，但须标明尚未确认正确性，不作为需求符合的证明。

## 2. 设计与断言

| 编号 | 适用条件 | 要求 |
| --- | --- | --- |
| UT-05 | 每个场景 | 名称、准备、动作与断言表达清楚的行为，失败可定位；组织方式遵循项目约定。 |
| UT-06 | 每个场景 | 断言验证契约相关结果、状态、错误或副作用，并能识别关键错误；禁止恒真、无关或无依据放宽的断言。 |
| UT-07 | 内部实现或依赖交互 | 优先验证对外行为；调用次数、顺序仅在属于契约时断言，避免绑定无关实现细节。 |
| UT-08 | Fixture/Helper/参数化 | 关键输入、期望与触发条件可理解；复用不得隐藏场景含义。 |

“非空”“无异常”等只有在构成完整契约时才可单独作为断言。不照搬被测算法计算答案；可采用独立模型或性质验证。测试数据遵循实际输入域，不受英文命名偏好限制。

## 3. 隔离、确定性与速度

| 编号 | 适用条件 | 要求 |
| --- | --- | --- |
| UT-09 | 使用 Fake/Stub/Mock | 替身符合相关契约且不绕过被测逻辑；重要保真风险有验证依据。 |
| UT-10 | 访问外部资源或状态 | 资源可控；不隐式使用线上服务、生产数据或不可控凭据。 |
| UT-11 | 可执行用例 | 不依赖用例顺序或未重置的共享状态；清理连接、后台任务、全局修改和临时资源。 |
| UT-12 | 异步、并发、时间或随机行为 | 等待真实完成条件，控制相关不确定因素；不以固定等待或重试掩盖竞态。 |
| UT-13 | 例行套件 | 执行成本符合项目预算，超时明确记为失败；区分构建/初始化与测试体耗时。 |

优先使用合适的真实轻量实现，必要时隔离依赖。UT 不能替代真实协议兼容性验证。发现偶发失败须保留失败与重跑结果；一次重跑通过不能证明已修复。

## 4. 执行与故障归因

| 编号 | 适用条件 | 要求 |
| --- | --- | --- |
| UT-14 | 声称已验证 | 真实运行对应代码与测试，记录命令、工作目录、代码状态、退出码和用例统计；零发现不算通过。 |
| UT-15 | 判断变更引入或历史失败 | 使用相关基线或有效隔离对照；缺少基线明确标记，不凭最终日志推断责任。 |
| UT-16 | 任意阶段失败 | 保存证据，区分测试、环境、业务与未决原因；新发现的缺陷照常分析，不因阶段不同丢弃。 |
| UT-17 | 修改测试、配置、依赖或被测逻辑后 | 重跑受影响检查；回归范围包含共享资源与配置的影响。 |

测试未复现缺陷不等于证明缺陷不存在。已证实无效的测试构造可修正或撤回；不得删除有效失败证据、吞异常或改变正确预期来制造通过。静态发现与运行确认必须分开。

## 5. 覆盖率

| 编号 | 适用条件 | 要求 |
| --- | --- | --- |
| UT-18 | 报告覆盖率 | 明确工具、版本、测量单位、目标分母、测试集合与排除策略，保留原始数据。 |
| UT-19 | 覆盖率门禁 | 使用项目约定阈值；必需目标失败或未执行时，不通过动态排除放行。 |
| UT-20 | 分片或模块汇总 | 核验代码快照、插桩配置、路径及分片完整性；合并原始数据，不直接平均百分比。 |

行口径增量覆盖率为“Diff 中命中的可执行且可测量行 / Diff 中纳入的全部可执行且可测量行”。采用语句/区域口径时明确标注；关键分支按风险核验。覆盖率不证明断言有效。

分母为零是不适用，合法空集与工具错误须区分。失败目标的数据可标未知，但不能从必需范围消失；成功子集数据仅用于诊断。缺陷修复后的回归测试正常纳入统计。

## 6. 验收与交付

| 编号 | 适用条件 | 要求 |
| --- | --- | --- |
| UT-21 | 报告结论 | 分开报告测试质量、执行结果、任务完成度；不得用其中一项代替其他项。 |
| UT-22 | 未修复业务缺陷 | 保留正确断言与复现；执行不能标为通过，但测试本身可符合质量规范。 |
| UT-23 | 跳过、预期失败或偶发失败隔离 | 单独统计，不计作 PASS；临时例外说明原因、责任人、跟踪项与退出条件。 |

**测试质量**逐规则判定：PASS（证据满足）、FAIL（证据违反）、NOT_APPLICABLE（条件不成立并说明）、UNKNOWN（证据不足）。所有适用要求满足才可称质量合格；真实业务缺陷导致断言失败，不自动构成质量违规。

**执行结果**按真实 PASS/FAIL/SKIP/XFAIL/未执行报告。必需用例失败或未执行，不能称执行验收通过。预期失败须限定原因，框架支持时检测意外通过；不把环境问题伪装成已知业务失败。

**任务完成度**说明范围已完成、部分完成或阻塞。发现并证实业务缺陷可以完成补测任务，但执行仍失败；本规范不据此判断整个项目能否合并或发布。

例外保留原判定及有权批准者的记录、适用范围、补偿措施和撤销条件，不能改称无条件合格。所有结论都须能追溯到测试、代码、配置或运行记录；无法获取的证据如实说明。
